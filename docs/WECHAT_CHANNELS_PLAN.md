# 微信视频号本机捕获与统一下载计划（1.3.0）

## 目标

在不复制 `ltaoo/wx_channels_download` 运行时代码的前提下，用 Python 3.11+ 标准库和本项目自有 JavaScript，为下载中转站增加 Windows 微信桌面客户端的视频号发现、预览、质量选择、下载、必要解密、校验及 Eagle 导入闭环。

外部项目用于确认可观察链路：微信桌面页经受信任的本机 HTTPS 代理加载，完整 feed 既可能出现在页面 JSON，也可能只存在于微信资源模块内部 `finder*` API 的返回对象，媒体最终由本机下载。我们的实现不引入它的 Go、Gin、SunnyNet、Gopeed、证书、图标或 UI，也不把其 Commons Clause 代码合并到本项目。

## 统一职责

```text
微信桌面客户端
    │ 用户显式开启的本机受控 HTTPS 捕获
    ▼
WechatChannelsCaptureService (Python)
    ├─ 证书/代理生命周期与精确恢复
    ├─ 只处理允许的视频号主机
    ├─ 注入本项目自有 bridge.js
    └─ 会话内保存短期 URL/头/解密键
            │
            ▼
页面 bridge.js
    ├─ 读取页面 JSON 与内部 finder API 已返回的结构化 feed
    ├─ objectId 内容身份与多质量归组
    ├─ 在微信原操作栏插入当前视频下载按钮
    ├─ 普通点击选择当前播放质量，悬停菜单列出其他实际质量与有凭据的原始视频
    └─ 只提交已登记 objectId/variantId，不执行下载/解密/Eagle
            │
            ▼
WechatChannelsCaptureService → MediaCoordinator
    ├─ 服务端复验会话 objectId / variantId
    ├─ 页面直接创建下载并导入 Eagle 任务
    ├─ 桌面“微信视频号”页保留候选核对和手动创建
    ├─ 候选按旧到新排列，首次定位最新项
    ├─ 统一 download_plans / 进度 / 停止 / 重试
    ├─ 下载、必要流式解密、FFmpeg 合并
    ├─ ffprobe 校验与本机输出
    └─ 仅下载或 Eagle 官方 API 导入
```

Chrome/Edge/Firefox 扩展仍只负责浏览器网页；微信来源不会塞入扩展 popup，也不会复制第二套浏览器下载器。IDM hook 保持快速入队，不参与捕获。

## 硬边界

1. 视频号捕获首次默认关闭；只有用户点击开始后才安装/信任本程序证书和修改当前用户代理。
2. 捕获服务固定监听 `127.0.0.1`，只对明确的视频号主机 TLS 终止，非目标连接隧道转发；不能作为局域网或公网开放代理。
3. 开启前保存完整代理配置。原 HTTP/Mixed 代理继续作为固定上游；PAC/WPAD 由 Windows WinHTTP 按 URL 解析并在改写前预检，TUN/无代理决定继续直连。只有当前代理仍属于本程序时才自动恢复；外部代理变化不能被覆盖。
4. 证书和私钥每机生成。私钥、Cookie、Authorization、解密键、完整签名媒体 URL 和完整 feed 不进入 Git、发行包、SQLite、日志或诊断。
5. 内容身份只认结构化 objectId。标题、作者、封面、时长和媒体必须来自同一 feed；不按时间、大小、CDN 地址或标签页标题猜测。
6. 视频号应用层加密只在页面明确给出 decodeKey 时处理；独立实现的 ISAAC-64 来自 Bob Jenkins 公共领域算法规范，不复制无许可证第三方仓库的解密代码。DRM 内容继续阻断。
7. 用户原下载文件不移动、不修改、不删除。仅清理有计划归属的中间文件；最终仅下载文件保留并可稍后补导 Eagle。
8. 停止、退出或启动中途失败时，先尝试恢复程序拥有的 WinINET 配置，再等待代理监听和其他后台线程退出；恢复失败保留租约，不把死回环端口当作成功状态。
