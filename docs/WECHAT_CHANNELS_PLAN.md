# 微信视频号本机捕获边界

本文描述当前视频号实现，不记录历史方案。

## 目标

- 用户明确启动后，从 Windows 微信客户端当前播放内容建立可核对的媒体候选。
- 支持当前质量、feed 明确提供的其他质量，以及有效凭据下的原始视频。
- 复用桌面统一下载、校验、Eagle 导入和文件安全状态机。
- 在 VPN、系统代理或 PAC/WPAD 环境中保持原有上游线路。

## 非目标

- 不绕过 DRM、账号权限、付费权限或平台访问控制。
- 不复制或分发外部项目的代理、下载器、证书、UI 或实现代码。
- 不把视频号能力放进浏览器扩展或 IDM hook。
- 不把 Cookie、签名、解密信息或完整 feed 持久化。

## 启动流程

1. 用户在桌面“微信视频号”页点击“开始捕获”。
2. 后台读取并保存当前 WinINET 代理快照。
3. 检查端口、证书和可用上游；任何失败都在改写系统代理前结束。
4. 启动只监听 `127.0.0.1` 的本机 HTTPS 代理。
5. 将 Windows 代理临时指向本机捕获端口，并保留原 HTTP/Mixed 或 PAC/WPAD 上游。
6. 微信页面重新进入内容后，页面 bridge 观察已经返回的结构化 feed。

首次使用时，根证书由本机生成，私钥不离开当前电脑。证书信任必须由用户亲自确认名称为“留底下载器 微信视频号本机捕获根证书”的 Windows 安全警告。

## 捕获范围

- 只对明确的视频号页面和资源目标执行 TLS 终止。
- 普通 HTTP、非目标 HTTPS 和其他应用流量透明转发。
- 代理不能监听局域网或公网地址，不能成为通用开放代理。
- HTTP/Mixed 上游直接串联；PAC/WPAD 使用 Windows WinHTTP 按目标 URL 解析。
- 保留明确的本地域名、主机和网段绕过；忽略会让所有公共请求脱离已配置 VPN 上游的独立全局 `*`。
- 纯 SOCKS 或不受支持的 PAC 结果必须明确报错，不静默直连。

## 候选与身份

页面 bridge 从微信自身已经返回的数据中提取：

- `objectId`
- `variantId`
- 标题、作者、封面和时长
- 当前质量和其他明确质量
- 当前会话所需的最小请求上下文

URL、媒体路径和结构化身份无法唯一绑定当前内容时拒绝创建任务。不得按标题、时间或候选顺序猜测。

## 原始视频

原始视频只有同时存在有效 `encfilekey` 和 `token` 时才显示。原始请求只保留这两个访问参数，不携带 `basedata`、`sign`、`svrnonce` 等转码上下文。

明确质量档继续保留自己完整的签名查询和质量标志。原始档与转码档必须作为同一内容的不同 variant 展示。

## 下载与交付

候选提交后由 `MediaCoordinator` 创建普通持久计划。桌面端负责：

- 受控下载
- 必要的流式前缀解密
- FFmpeg 封装
- FFprobe 校验
- 仅下载或 Eagle 导入
- 用户明确选择后的安全删除

停止捕获不停止已经提交的任务。

页面“下载”的 Eagle 能力回调缺失、异常或返回不可用时，一律安全降级为本机保留任务；页面按钮本身不设置导入后删除。只有桌面中明确标注删除本机副本的 Eagle 操作可以设置删除意图。

## 停止与恢复

停止捕获、程序退出、升级和卸载必须：

1. 停止接受新连接。
2. 恢复程序仍拥有的完整代理快照。
3. 释放监听端口和捕获租约。
4. 清空未提交候选和敏感内存会话。
5. 保留已经提交的持久下载计划。

如果其他软件在捕获期间修改了代理设置，程序不得覆盖对方的新值，而应提示人工处理。

## 验证

- 自动测试覆盖证书、代理快照、PAC/WPAD、HTTP、HTTPS CONNECT、feed 绑定、原始参数、明确质量、解密、FFmpeg/FFprobe、退出恢复和秘密不落盘。
- 用户实际 VPN 开启状态下的微信候选、下载和停止恢复必须进行最终人工复验。
