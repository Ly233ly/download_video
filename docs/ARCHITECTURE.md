# 当前系统架构

本文只描述当前实现。历史架构和已经被替代的方案由 Git 历史保存。

## 总体结构

留底下载器由五个边界清晰的部分组成：

1. 浏览器扩展发现媒体、形成候选组、展示选择并提交任务。
2. Windows 桌面程序持久化计划，执行下载、合并、校验和 Eagle 导入。
3. IDM hook 快速接收完成事件并唤醒后台处理。
4. 微信视频号捕获服务在用户明确启用后提供独立的本机来源。
5. Windows 安装器和托盘宿主管理安装、升级、回滚、快捷方式和生命周期。

浏览器不负责最终文件，Eagle 不由扩展直接访问，IDM hook 不执行网络或哈希工作。

## 浏览器媒体流程

```text
网页播放器与网络请求
        ↓
扩展内容脚本和后台发现
        ↓
媒体候选组（内容身份、预览、质量、音轨）
        ↓
用户核对并选择输出方式
        ↓
认证回环 API 提交下载计划
        ↓
桌面 MediaCoordinator
        ↓
下载 → 合并 → FFprobe 校验 → 本机完成或 Eagle 导入
```

扩展把同一内容的不同 URL、质量和音轨归入一个候选组。无法证明属于某个内容的分片、预加载请求和诊断资源不进入默认下载列表。

本机健康接口同时发布 `eagleAvailable` 能力。扩展只把它用于选择交付方式：明确为 `false` 时，单个和批量操作默认提交 `importToEagle=false`；旧扩展仍提交导入时，本机 API 会再次降级并同时关闭 `deleteAfterImport`。因此 Eagle 缺失只能关闭归档动作，不能关闭下载动作。

扩展的连接、任务和候选请求分别使用最新请求代次；迟到响应不能覆盖较新状态。即使本地仍保存配对令牌，只要健康请求失败，依赖桌面的动作全部关闭并保持低频重连。popup 卸载会使在途代次失效并清除全部定时器。

候选选择只原位更新列表行状态，不能为了切换选中项重建整个滚动容器；候选集合真正变化时才允许重绘，并保留滚动位置。

单页应用的 history、fragment 和内容脚本位置变化只重置发现上下文并继续累积当前标签候选；完整文档的 committed/loading 导航才按用户自动清理模式删除旧候选。

完整文档清理属于导航边界，不能排入异步闹钟：高频模式在顶层 `onBeforeNavigate` 执行，默认模式在顶层 `onCommitted` 执行。若 Manifest V3 Worker 的设置或媒体快照尚未恢复，按标签暂存 `loading`/`committed` 边界；`findMedia` 接收首个新媒体以及弹窗读取权威快照前都会先冲洗待处理边界。这样旧文档清理永远不会落到新文档候选入库之后。

本机 API 只监听回环地址。首次安装由安装器写入的一次性凭据完成自动连接；凭据消费后，扩展请求必须同时满足来源校验、已登记状态和随机令牌认证。令牌丢失时只允许数据库中完全相同的扩展 Origin 重新签发，新令牌会立即替换旧令牌。桌面界面不展示人工配对码。

## 下载执行

桌面端根据计划选择执行路径：

- 普通直链：FFmpeg 或受控 HTTP 下载。
- HLS/DASH：FFmpeg 读取清单并输出完整文件。
- 分离音视频：分别获取轨道后使用 FFmpeg streamcopy 合并。
- 页面解析：固定 yt-dlp 与 Deno 解析格式，再交给 FFmpeg 下载；页面 Cookie 和 Authorization 只用于解析，不跨主机转发给媒体 CDN。
- 微信视频号：使用当前内存会话中的最小请求上下文，必要时执行前缀解密和封装。

输出必须经过 FFprobe 校验。明显的时长、流或容器错误会阻止交付，不会把失败文件标成完成。

桌面下载默认按任务读取 Windows 系统代理。Eagle、本机 API、控制信号和回环通信始终直连。

## 任务状态

计划和任务状态由桌面数据库统一保存。界面只投影真实状态，不自行推断完成：

- 排队与准备
- 下载中
- 合并或校验中
- 等待 Eagle
- 仅下载完成
- 已导入
- 失败、停止或需要重新从来源创建

只有“仅下载完成”或“已导入”可以显示 100%。浏览器通过认证接口读取同一状态。

## Eagle 与文件所有权

Eagle 导入和来源更新只调用官方本地 Web API，不直接修改 `.library`。

浏览器与视频号下载链不依赖 Eagle。Eagle 不可用时计划在校验后进入“仅下载完成”，文件留在“已完成”目录，之后可以直接补导。IDM 链接收的文件已经由 IDM 下载完成，它的业务动作是导入，所以可以保持等待 Eagle，但不得占用或阻塞媒体下载队列。

补导通过数据库 `BEGIN IMMEDIATE` 原子占有“已完成”计划并创建或复用唯一导入任务，避免并发点击产生孤立任务。重复内容被指纹表命中时，关联计划终结为“Eagle 已有相同内容”，并清除删除意图、保留本机文件。

文件分为三类：

- 用户或 IDM 原文件：永不移动、删除或修改。
- 程序临时分片和中间文件：只有存在明确任务归属时才能清理。
- 程序创建的最终副本：只有计划明确选择删除、Eagle 已确认导入，并通过计划路径、任务路径和“已完成”目录归属校验时才能删除。

任何归属不明确、导入失败、文件锁定或目录外路径都必须保留。

## 程序缓存

`ProgramCacheManager` 只管理留底下载器根目录中的 `临时`、`预览` 和旧版 `media-download.log`。它不把 `已完成` 目录计入缓存，也不遍历或删除该目录。

手动清理删除未被活动计划使用的缓存；自动清理由后台服务每天检查一次，只删除最后修改时间超过用户保留期的缓存。保留期为 `0` 时关闭自动清理。活动计划 ID、正在运行的进程、数据库中仍由活动计划引用的预览，以及链接、目录联接和无法安全读取的路径都会被跳过。预览删除后同步清除数据库中的失效路径。

导入后保留期清理另行要求计划路径、关联任务路径和 `留底下载器/已完成` 根目录完全一致。IDM 导入批次与此清理使用独立预算；等待 Eagle 的队列不能让清理永久饥饿。

缓存维护与下载、Eagle 导入队列隔离；统计或删除失败只能留待下次重试，不能停止业务循环。

## IDM 流程

```text
IDM 下载完成
    ↓
IdmEagleHook 快速入队并发送唤醒信号
    ↓
后台等待文件稳定
    ↓
有可靠来源时附加来源；无来源时直接导入
    ↓
Eagle 官方 API
```

hook 不进行哈希、网络请求或长时间等待。网站关闭只接受扩展明确发送的事件，不能从无来源文件反推。处理服务会隔离单轮数据库、文件系统或 Eagle 异常，确保唯一后台线程仍能进入下一轮。

## 微信视频号流程

视频号捕获默认关闭。用户点击“开始捕获”后：

1. 保存当前 WinINET 代理快照并验证捕获前置条件。
2. 启动只监听回环地址的 HTTPS 捕获代理。
3. 对明确的视频号目标终止 TLS；其他连接透明转发。
4. 页面 bridge 读取微信页面已经返回的结构化 feed，并按 `objectId` 与 `variantId` 建立候选。
5. 用户从微信操作栏或桌面候选页创建计划。
6. 任务交给同一个 `MediaCoordinator` 下载、校验和导入。

已有 HTTP/Mixed 代理直接作为上游；PAC/WPAD 使用 Windows WinHTTP 按目标 URL 解析。VPN 绕过列表中的明确主机、本地域名和网段规则继续生效，但独立的全局 `*` 不参与捕获代理的上游判定，否则 WinINET 被切换到回环捕获代理后会让整个 VPN 上游失效。无法获得安全上游时，启动在改写系统代理前失败。

“原始视频”只保留 `encfilekey` 和 `token`；明确质量档保留自己的完整签名参数。无法唯一绑定当前视频时拒绝提交。

停止、退出、升级和卸载会恢复程序仍拥有的代理设置，释放端口并清除未提交的敏感会话。其他软件后来修改的设置不会被覆盖。

## 数据库

SQLite 使用 `PRAGMA user_version` 管理结构迁移。当前结构版本为 `6`。

数据库保存任务、计划、来源、网站规则、浏览器连接认证状态和必要的安全归属信息。Cookie、Authorization、签名 URL、视频号解密信息和临时会话不持久化。

迁移必须是一次性的、可测试的结构步骤，不得用每次启动的大范围更新替代。

## UI 与并发

Windows 主界面只在 Tk 主线程执行控件投影。下载任务最多读取 200 条并在一个连续滚动列表中展示，不提供额外页码；IDM 与视频号的大型集合仍使用有界分页。下载、诊断、Eagle 探测、视频号操作、证书检查、预览读取和批量清理在后台运行，并通过有界队列和代次校验返回结果。

扩展对标签页、站点状态、候选快照和任务轮询分别维护最新请求代次；跨页面切换会使旧代次失效，卡住的响应头与 JSON 正文都受统一超时预算约束。桌面健康接口对 FFmpeg、FFprobe、yt-dlp 和 Deno 使用 single-flight 并行探测，多个刷新请求共享同一轮结果。

数据库为任务状态/更新时间、计划创建时间、计划任务关系与候选组关系维护幂等索引；UI 摘要只关联活跃计划，来源事件匹配只读取最近的有界候选，避免历史数据增长使轮询退化为全表排序或无界评分。

Tk 8.6 在 Windows 上会把 Canvas 平滑曲线栅格化为没有抗锯齿的线段，因此自绘控件不再依赖 `smooth` 多边形。四角由纯标准库代码以 8×8 子像素覆盖率采样并平均颜色，按主题、半径、边框和背景在顶层窗口内缓存；直边使用原生矩形与四角无缝重叠。按钮、面板、导航、选择器、徽标、滚动条和进度条每次更新只重建固定数量的有界画布项。

小尺寸连接状态点使用独立的对称圆覆盖率采样，不调用 Tk 的非抗锯齿椭圆。任何依赖主题的默认颜色都在控件实例化时从当前 `UI` 调色板读取，而不是写入 Python 默认参数；切换主题时，控件树会同时映射画布背景、内部颜色状态并使图片型圆角/圆形缓存表面失效重绘。

Canvas 自绘控件在创建时直接登记一次空闲绘制，并在销毁时取消尚未执行的回调，避免首次显示依赖后续点击，也避免快速切页留下失效 Tcl 命令。带常规 Tk 子控件的圆角容器根据圆角半径、边框宽度和抗锯齿覆盖范围计算最小内容边距，矩形内容窗口不得进入四角曲线区域。

系统托盘由 `launcher/Launcher.cs` 的 Windows Forms 宿主管理。Python 不替换窗口过程。

## 发行边界

PyInstaller 生成冻结后端，安装载荷整体嵌入单文件安装器。用户 ZIP 不包含外置源码、构建脚本、source map、开发机数据或用户状态。

公开仓库提供当前对应源码、构建脚本、固定第三方源码和许可证。发行前必须验证版本同步、测试、载荷完整性、安装、升级、回滚、卸载和源码暴露门禁。
