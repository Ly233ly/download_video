# 桌面软件全面性能审计

日期：2026-07-29
范围：桌面主窗口、媒体任务、视频号捕获、IDM 导入、设置、诊断，以及这些页面共用的数据刷新、滚动、图片和窗口重绘路径。

> 状态说明：本文记录的是工作区源码在前一轮优化后的结果，不代表当前已安装程序。2026-07-29 核验发现，当前安装版仍为 1.4.3，工作区为 1.4.5；安装版尚未包含这里的全部优化。线程、after、主线程阻塞、安装版/源码基线和未确认风险，以 `docs/TK_PERFORMANCE_INITIAL_AUDIT_2026-07-29.md` 为准。

## 用户目标

本轮目标不是只缩短某个函数的耗时，而是让软件形成稳定、可预期的整体手感：

- 启动后尽快可操作；
- 切页、滚动和拖动窗口时不粘、不跳、不留残影；
- 任务或候选很多时，后台更新不会拖慢当前页面；
- 长时间运行后，内存、回调和刷新成本不会持续增长；
- 优化必须是通用机制，不针对某个网站写特殊分支。

## 审计角度与结论

| 角度 | 审计发现 | 处理结果 |
| --- | --- | --- |
| 主线程 | 每次全局刷新都会同步处理隐藏页面；IDM 1000 条压力数据的强制刷新最差接近 200ms | 只刷新当前页；后台健康探测沿用异步结果；未变化的列表不再强制重建 |
| 启动 | 五个页面和所有设置子页一次性创建，初始约 402 个控件 | 首屏只创建下载任务页，其余页面延迟创建；设置子页也按需创建 |
| 绘制与布局 | 圆角 Canvas、动态换行、列宽、滚动区和预览比例会在一次拖动中重复重绘 | 合并到空闲周期执行；复用 Canvas 图层；相同尺寸、状态和文字不再重复配置 |
| 长列表与图片 | 媒体、视频号和 IDM 的投影会重复处理未变化的数据；缩略图可能重复解码 | 按数据修订号做增量投影；缩略图按路径、大小和修改时间复用，并限制为 64 项 |
| 数据库与磁盘 | 媒体列表“读取”时会顺带写入导入状态；顶部计数需要读取完整计划 | 导入状态恢复改到一次性恢复阶段；列表读取保持只读；顶部使用轻量汇总查询 |
| 后台轮询 | 视频号静态文件身份和系统代理状态被高频重复检查 | 静态身份改为显式失效缓存；代理状态缓存从 5 秒延长到 30 秒，实际任务路由仍即时读取 |
| 输入手感 | 每个滚动区都在顶层绑定滚轮；细小触控板增量也会立即跳动一整格 | 每个窗口只保留一个滚轮路由；根据鼠标所在控件选择最近滚动区；高分辨率增量先累积再滚动 |
| 响应式布局 | 详情标题和三项操作在窄宽度互相挤压，容易出现单字掉行 | 窄宽度下操作组自动移到标题下方，宽屏恢复同行 |

## 可重复压力结果

测试环境为同一台 Windows 电脑、同一 Python/Tk 运行时。IDM 场景包含约 1000 条任务；优化后场景连续执行 200 次刷新。所有数字均由 `tests/visual_ui_fixture.py` 在本轮生成。

| 媒体压力场景启动 | 805.8ms | 481.7ms | -40.2% |
| IDM 压力场景启动 | 860.1ms | 399.5ms | -53.6% |
| 首屏控件数 | 402 | 223–256 | -36.3% 至 -44.5% |

## 当前健康判断

工作区源码中的已知 P1 结构问题已有对应优化，确定性测试未再复现旧版接近 200ms 的强制刷新。当前安装版仍为 1.4.3，因此不能宣称用户正在使用的程序已经解决 P1。
