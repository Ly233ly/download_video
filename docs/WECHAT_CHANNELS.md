# 微信视频号：实现、故障排查与验收

本文是项目中微信视频号技术问题的唯一权威文档。架构、当前视频识别、画质、代理/VPN、下载失败、隐私边界和验收记录统一维护在这里；其他文档只保留用户入口、项目规则或链接。

## 当前结论

- 视频号捕获默认关闭，只能由用户在留底桌面端明确启动。
- 下载、必要的前缀解密、封装、FFprobe 校验和 Eagle 导入全部在本机完成。
- Eagle 是可选能力；未安装或未启动时，视频号仍下载到电脑并保留文件。
- 页面只在强证据能够唯一确认当前内容时创建任务；歧义时拒绝，绝不按最新候选、返回顺序、作者或时长猜测。
- 2026-08-21 已完成真实修复验收：此前稳定出现“未能确认当前视频”的 Morph 52 秒视频下载成功，随后连续 5 条不同视频全部完成且未串片，独立验收 PASS。

## 用户流程

1. 打开留底桌面端的“微信视频号”页面，点击“开始捕获”。
2. 首次使用时，由用户亲自确认名称为“留底下载器 微信视频号本机捕获根证书”的 Windows 安全警告。
3. 在 Windows 微信客户端重新进入并播放目标内容。
4. 点击视频操作栏中由留底加入的“下载”；悬停可选择其他实际画质或有效的原始视频。
5. 任务创建后可以停止捕获，已经提交的下载会继续执行。

页面脚本升级后必须重新进入视频号页面，才能加载新版识别逻辑。只拖动播放进度通常不会重新注入脚本。

## 捕获架构

```text
用户开始捕获
  → 保存 WinINET 代理快照
  → 检查证书、端口和可用上游
  → 启动仅监听 127.0.0.1 的 HTTPS 捕获代理
  → 临时把 Windows 代理指向捕获端口
  → 页面 bridge 读取微信已经返回的结构化 feed
  → 登记候选并确认当前 objectId
  → 页内或桌面提交 variantId
  → MediaCoordinator 下载、解密、封装、FFprobe、保留或导入 Eagle
  → 停止时恢复代理快照并清除未提交敏感会话
```

只对明确的视频号页面和资源目标执行 TLS 终止；普通 HTTP、非目标 HTTPS 和其他应用流量透明转发。捕获代理不得监听局域网或公网地址，也不能成为通用开放代理。

## 候选与当前视频识别

页面 bridge 从微信自身返回的数据中提取 `objectId`、标题、作者、封面、时长、媒体地址、质量规格和当前会话所需的最小上下文。所有候选可以登记，但只有当前内容可以激活和提交。

当前内容使用以下强证据，证据冲突时一律拒绝：

1. 页面或当前卡片白名单属性中的唯一 `objectId`。
2. 媒体路径加稳定 `encfilekey`。
3. 唯一、位于当前视口且正在播放的视频元素，与权威详情主对象的短期绑定。
4. 当前视频元素的唯一 `poster` 封面。
5. 当前卡片中规范化后的完整标题。

作者、时长、地址栏残留 ID、候选数量、接口返回时间和“最近一条”都不能单独授权下载。有当前播放器时，地址栏 ID 还必须得到另一项强证据佐证。

### 共用 CDN 路径

微信大量视频共用 `/stodownload` 路径。只比较主机和路径会把相邻预加载内容视为同一媒体，因此这类地址必须同时匹配内存中的 `encfilekey`。短期 `token` 或 `sign` 轮换不影响身份；完整签名不得持久化。

不含 `encfilekey` 的通用 `stodownload` 路径不构成身份，即使内存里恰好只有一个候选也不能猜测。

### `blob:` 播放地址

MSE 播放器可能只暴露 `blob:` 地址，无法直接对应 CDN。bridge 只把权威当前详情绑定到视口内唯一的播放元素，并在 `loadstart`、`emptied` 或实际时长改变时清除旧绑定。屏外、暂停或相邻预加载视频不能提供当前封面或绑定。

### 详情响应中的关联推荐

`finderGetCommentDetail` 可能一次返回主视频和数十条关联推荐。递归扫描仍登记全部候选，但当前内容只取 `data.object` 的唯一直接主对象：

- `data.object` 只有一个可归一化 ID：允许绑定当前播放元素。
- 推荐列表包含任意数量或以任意顺序返回：只能登记候选，不影响当前项。
- `data.object` 缺失，或直接包含两个不同 ID：拒绝绑定。

这条规则修复了“目标视频已经进入候选，但连续刷几条后仍提示未能确认当前视频”的现场问题。

## 画质与原始视频

- 当前质量和其他明确质量保留各自真实签名参数和 `deliverySpec`。
- 页内主“下载”、桌面下拉框和未传画质的后台提交，统一优先选择带 `deliverySpec` 的最高明确画质。
- “原始视频”只有同时存在有效 `encfilekey`、`token` 和 feed 原始文件大小时才显示。
- 原始请求首先只保留 `encfilekey` 和 `token`，不能携带转码选择器。
- 明确画质的 `X-snsvideoflag` 大小写不敏感地替换，只能存在一次。

精简原画地址收到 HTTP 400/403 时，可以回退到同一 feed 捕获的完整地址，但必须同时满足：

- 主机、端口、路径一致；
- `encfilekey` 和 `token` 一致；
- 响应头和实际下载字节数都与 feed 声明的原始文件大小完全一致。

任何一项不满足都拒绝，不能把转码或低清文件标成原始视频。

## 网络代理与 VPN

捕获上游按以下优先级解析：

1. 可安全解析的 PAC/WPAD；
2. 已启用的 WinINET HTTP/Mixed 代理；
3. 留底保存的 HTTP/Mixed 代理；
4. 直连。

自动模式只在保存端口当前可达时动态串联，不可达时静默直连。手动模式要求端口可用，否则指向“设置 > 网络代理”。纯 SOCKS 端口不能直接填写为 HTTP/Mixed 上游。

VPN 绕过列表中的明确本地域名、主机和网段继续生效；会切断全部公共微信请求上游的独立 `ProxyOverride=*` 不参与公共视频号域名判定。任何上游无法安全解析的情况都必须在改写 Windows 代理前失败。

停止捕获、退出、升级和卸载必须先恢复程序仍拥有的代理快照，再释放端口和租约。如果其他软件在捕获期间修改了代理，留底不得覆盖对方的新值；最终状态需要人工或恢复逻辑核对。

## 下载、校验与缓存

候选提交后由 `MediaCoordinator` 创建普通持久下载计划。下载过程包括：

- 有界 HTTP 重试；视频号媒体首次 HTTP 400 时可对同一地址使用 `Range: bytes=0-` 重试一次；
- 仅对 feed 声明的加密前缀执行流式解密；
- FFmpeg 封装；
- FFprobe 验证视频轨、音轨、分辨率和时长；
- 本机完成或通过 Eagle 官方本地 API 导入。

成功任务的完整 `wechat-decrypted-*.mp4` 中间文件属于程序缓存，不是失败残片，可由“设置 > 文件管理”按安全缓存规则清理。失败的 `.part`、不完整输出或无法验证媒体不得进入“已完成”目录。

## 故障矩阵

| 现象 | 主要证据 | 处理 | 验收 |
| --- | --- | --- | --- |
| 开始捕获后黑屏、候选始终为 0 | 捕获上游丢失或回环端口失效 | 继承可用 PAC、HTTP/Mixed 或自动备用端口；不可达时在改系统代理前停止 | 微信可播放；停止后代理与开始前一致，租约清除 |
| Windows 指向已经关闭的回环端口 | 代理开启但端口不监听 | 启动前检测；使用“修复代理冲突”只清理可验证的失效本机代理 | 微信原网络恢复，不删除其他软件代理 |
| 有候选但提示“未能确认当前视频” | 没有 active；`blob:`；共用路径；详情带大量推荐 | 使用稳定媒体标识和 `data.object` 唯一主对象绑定；歧义继续拒绝 | 目标页内按钮创建正确任务；连续切换不串片 |
| 页内下载了相邻视频 | 旧地址栏、预加载响应或最近候选被误当当前 | location、卡片、播放元素、媒体和封面证据聚合；冲突拒绝 | 下一条晚到不能抢 active；A/B 证据冲突不创建任务 |
| 默认任务很快 0 字节失败 | 桌面误选原画或签名过期 | 默认明确 `deliverySpec`；重新播放；原画按严格回退验真 | `media_streams.label` 为明确画质并实际落盘 |
| 原画 HTTP 400/403 | 精简地址被 CDN 拒绝 | 同地址 Range 重试；再使用同 feed 完整地址并验证身份和大小 | 成功即停止重试；不一致报错并清理临时输出 |
| `wechat_original_size_mismatch` | 完整地址返回内容大小与 feed 原画声明不同 | 拒绝低清/转码冒充原画 | 不产生完成文件，不导入 Eagle |
| `wechat_download_incomplete` | 实际字节小于响应长度 | 删除失败临时文件，重新播放捕获 | 最终目录无不完整文件 |
| FFmpeg 或 FFprobe 失败 | 已下载但流、容器或时长无效 | 保留准确阶段错误，不归因于网络 | 失败任务不得显示 100% 或导入 |
| Eagle 未连接 | 下载有效但归档不可用 | 自动完成本机保留，之后补导 | `completed_local`，文件存在，不重新下载 |

## 诊断顺序

1. 先确认问题发生在任务创建前还是创建后。红色“未能确认”且数据库没有新计划，属于页面当前身份绑定；不要用下载、解密或 FFmpeg 解释。
2. 查看捕获状态、候选数、内部 API 观察数和安全诊断计数。候选增加但没有 active，重点检查详情主对象和播放元素绑定。
3. 有计划时检查 `status`、`error_code`、`downloaded_bytes`、所选质量标签和阶段信息。
4. 网络错误记录请求阶段、HTTP 状态、声明大小、响应 `Content-Length` 和实际字节；不得记录完整 URL、Cookie、解密键或签名值。
5. 任务完成后检查文件存在、FFprobe 至少一个视频轨、分辨率/时长与候选一致。
6. 停止捕获后核对 WinINET、监听端口和 `proxy-lease.json`。

## 隐私与安全边界

- Cookie、Authorization、完整签名 URL、`encfilekey` 值、`token` 值和解密键只在当前内存会话按最小范围使用。
- 数据库只保存去查询参数的来源、所选质量标签和不含秘密的 variant 标识。
- 页面失败诊断只记录原因和计数，不包含媒体 URL 或凭据。
- 不绕过 DRM、账号权限、付费权限或平台访问控制。
- 只下载用户有权保存和使用的内容。

## 自动回归

必须覆盖：

- 相同 `stodownload` 路径、不同 `encfilekey`；短期 token/sign 轮换；
- 通用路径缺少 `encfilekey` 时拒绝；
- `blob:` 当前播放、屏外预加载、无 `.slides-item` 页面；
- 同播放器切 A→B 时旧绑定失效；
- 地址栏 A 与当前卡片 B 冲突；
- 卡片同时含 A/B、重复封面、重复标题或弱元数据时拒绝；
- `finderGetCommentDetail={data:{object:[current], recommendations:[...]}}` 只激活 current；
- `data.object` 直接含 A+B 时拒绝；
- 默认明确画质、原画参数、HTTP 400/403 回退和严格大小验真；
- 代理快照、PAC/WPAD、自动/手动 HTTP 上游、停止恢复和秘密不落盘。
